# Original architecture: Cyrus IS Chess, 48K version

This is the specification the Zig port is checked against. The detail lives in the subsystem documents under [`arch/`](arch/00-overview.md), each with pseudocode, variable tables and evidence. This page summarises the facts that shape the port.

- **Canonical binary:** `reference/extracted/cyrus48-6000-9FFF.bin` (provenance in `reference/README.md`).
- **Disassembly:** `disasm/ctl/*.ctl` (source) → `disasm/cyrus.skool` and `disasm/cyrus.asm` (generated by `tools/scripts/build-disasm.ps1`).

## Facts that shape the port

The port also has an **extended mode** that lets this search run deeper with iterative deepening and time management (owner decision, 2026-10-21). It is specified in [EXTENDED_SEARCH.md](EXTENDED_SEARCH.md); the facts below describe the original itself.

1. **There is no clock.** [V] Nothing reads FRAMES or any timer.
   - A *level* fixes the search shape:
     - full-width depth D = 1, 2, 2, 2, 3, 4, 4, 4 for Levels 1–8;
     - forward pruning and threat-extension switches;
     - a Level-2 pre-pass for Levels 6–8.
   - P1/P2/P3 search exactly like Levels 1/4/8.
   - The maximum ply is 7. There is no iterative deepening, so a faster machine only finishes sooner; it never searches deeper.
2. **The only interruption is a key press.** [V] The keyboard is polled at every node (`$78BA`). The abort flag makes the search unwind, and it plays the best *completed* root move, or the best statically scored move if no root move has completed.
3. **Scores are one unsigned byte.** [V]
   - `$80` means equal; negation is `NEG`. The evaluation returns 0 for an illegal position.
   - A mate is `$FF` (mating side) or 1 (mated side), with no distance; the shortest mate is chosen separately.
   - Draws score `$78`/`$7E` ± the material term.
4. **The evaluation is noisy.** [V] Every evaluation increments `$BCCE` and adds its low bit (two bits on move 1). `$BCCE` is also stirred by the `R` register and by key-wait time. In the original it is effectively a random seed, carried from move to move.
5. **Behaviour depends on memory side effects, not just the position.** [V] The port reproduces these *effects*; it does not preserve the layout (AGENTS.md §6 Phase 3, decision 8):
   - move generation order = piece-slot order;
   - the search reads stale per-ply slots and compares list *addresses*;
   - the evaluation and move generator read variables stored in the board's off-board columns as if they were squares;
   - piece-record bytes, the game record and `$BCA0` persist between moves.
6. **Slot assignment depends on how a position was entered.** [V] The new-game set-up, set-up mode (scan order a-file first, rank 8 → rank 1) and promotions (the piece stays in its pawn slot) all assign slots differently.
7. **Castling rights are the "moved" bits.** [V] They are bit 4 of the king and rook type bytes. There is no en passant square: en passant comes from the last-move record `$BD58–$BD5B`, which set-up clears.
8. **The set-up legality check** [V] rejects a position if any of these hold:
   - a pawn is on rank 1 or 8;
   - a piece doesn't fit a free slot (K1 Q1 R2 B2 N2 P8; surplus pieces use free pawn slots, so a second king is impossible);
   - either king is missing;
   - the side not to move is in check.

   Nothing else is checked. After set-up: move number 10, `$BCA0 = $80`, no book, no en passant, no repetition history.
9. **The opening book** [V] is indexed by position in the generated move list, and it follows the game record from the standard start position only. Its random choice uses `$BCCE` mixed with `R`.
10. **Draw handling** [V]:
    - The search sees only stalemate, and a repetition at the root (`$BD5E ≥ 2`).
    - The 50-move rule and the threefold-style "6 reversals" draw are declared by the main loop.
    - Insufficient material is never detected.
11. **The engine always promotes to a queen.** [V] Under-promotion exists only for human moves: the type byte is overwritten after make.

## Known bugs in the original

These are tracked for the port in [DEVIATIONS.md](DEVIATIONS.md); deliberately preserved quirks are in [OBSERVATIONS.md](OBSERVATIONS.md).

| Bug | Where | Class |
|---|---|---|
| Move-list count wrong for ≥ 127 moves | `$79AF–$79B8` | A/B |
| Illegal book move 6…Be7 (Petroff line) | book data | B |
| Book matches the ply count by its low byte | `$7AD8` | A/B |
| Move lookup "not found" result ignored | `$7CBA`, `$7D00` | A (believed unreachable) |
| Castling through attacked squares is generated (it is caught at the root by the eval trick; to be confirmed) | `$7A61` | B if it reaches output |
| Exclusion list unbounded in HUMAN v HUMAN mode; promotion list overflows after 16 | `$BF00`, `$C048` | A in the original UI only; not used by the port |
